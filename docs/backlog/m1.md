### M1-019 (TIF-48) Always-cleanup on the failure path + guest-health precondition
- **status:** pending
- **owner:** build
- **blocked_by:** none
- **description:** A trial cleans up only on success, so a failed trial leaks `soffice` processes and run directories; a later trial can then read a foreign document and produce a misleading refutation (or, worse, a misleading pass). Found in log 27. Two parts: (a) ALWAYS cleanup on every exit path — kill `soffice`, remove the trial's guest run dir and temp profile, even when the trial throws; (b) a guest-health precondition evaluated before a trial starts: no stray `soffice` processes and no leftover run dirs beyond the current one, otherwise abort `uncertain` with a `guest-contaminated` guard failure rather than risk a contaminated reading.
- **acceptance:** a forced-failure trial leaves zero stray soffice processes and no leftover dirs; a trial started against a deliberately contaminated guest aborts `uncertain` with the guest-contaminated predicate (never verified, never refuted); tests cover both; verified on the VM.

### M1-028 (TIF-85) The C1 task text omits "save", so the arm cannot be scored on completion
- **status:** **In Progress** - TIF-85, via Coordinator PR #212; found 2026-11-22 by offline analysis of arm-002 transcripts. **Blocks a fair arm comparison**, not the arm itself
- **owner:** build
- **blocked_by:** none
- **description:** The C1 system prompt ends "Edit the open LibreOffice Calc document using the screenshot only. **Save and close it.**" (`src/baseline/planner.ts:78`).

  The per-trial task line does not: `Set the ${column} cell for record ${rowKey} to ${JSON.stringify(newValue)}.` (`src/baseline/c1-trial.ts:46`). A planner that treats the task line as the whole job types the value and stops.

- **acceptance:** the per-trial instruction states the full task, including that the change must be saved (and whether the document must be closed, which the current scoring depends on: `c1-judge.ts:32` treats still-open-and-modified as `modified`, not as a readable value); the change is recorded in docs/baseline/screenshot-agent.md as a **task-text** difference between arms, or both arms are given the identical text; any arm run before the fix is labelled with the text it used.

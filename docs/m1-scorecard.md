## Reliability row, regenerate

```bash
python3 scripts/m1-scorecard.py /tmp/m1-013/sweep-v2/trials.jsonl          # markdown
python3 scripts/m1-scorecard.py /tmp/m1-013/sweep-v2/trials.jsonl --json   # machine-readable
```

Counting rules (in the script header): the denominator is always 30, and an index without a record
is "not run". Only `verified` passes. Statuses that produced no verdict (harness, reset, deploy,
token, param, seed-mismatch) count as failures and are listed separately. The Wilson 95%
interval is over the recorded trials.

## Open risk: guest-side fixture convert

Two of the first five sweep v2 trials, plus pilot idx 3, ended `uncertain` with "fixture convert
did not produce fixture.xlsx within 60000ms". Each time the verdict was the correct safe outcome,
never a false success. But at that rate row 3 cannot reach 27/30. A successful convert takes a few
seconds, so the failures look like a convert that dies or hangs, not a slow one. The diagnosis
and proposed fix are tracked in `docs/coordination/m1-state.md`. The sweep is paused pending the
outer loop's decision.

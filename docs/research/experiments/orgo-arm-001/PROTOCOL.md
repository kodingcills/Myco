This is the infrastructure comparator for [MVD-003 §4.4](../../../product/mvd-preregistration.md#44-direction-c-mvd-003--tif-55). Ask which lifecycle operations a credit-only account can use, which guest state survives, how long each transition takes, and what a branch costs. Compare with the [Orgo teardown](../../findings/m2-01-competitive-teardown.md#72-orgo-orgoai-docsorgoai) and the Myco [reset baseline](../../../foundry/contract.md) and [live-restore failure](../../findings/m2-05-fast-vm-reset.md).

## Eligibility and spend

- Before any compute call, read the credit balance (expected $3.00), confirm the CLI-selected workspace is kodingcills's workspace, and check that its inventory is empty. Use the documented read-only compute offers endpoint to establish Small eligibility and price. The CLI 2.5.0 create help accepts 4 GB and 0.5 vCPU. Small is 0.5 vCPU, 4 GB, 20 GB, at $0.023 per running hour and $0.0014 per stopped hour. Orgo's create docs say a Free account always gets Medium even when specifying a size. If Free or if the read-only preflight cannot establish that an explicit Small hourly create will be honored, stop before the POST. Medium is outside scope. [Create](https://docs.orgo.ai/api-reference/computers/create) · [Sizes](https://docs.orgo.ai/guides/instance-types) · [Pricing](https://docs.orgo.ai/guides/pricing) · [Account limits](https://docs.orgo.ai/guides/account-limits) · [Agent API guide](https://www.orgo.ai/orgo.md)
- Work within $1.50 total, clean up at $1.20 observed spend, and leave the remainder as headroom for delayed billing. No top-up, plan change, payment flow, larger size, or other workspace. Use one source and at most one copy. Before any create, fork, or clone, refresh both balance and inventory and refuse if at the spend threshold or if the requested allocation would exceed two live records. Bound the base to a one-hour end where supported as an orphan backstop and bound the local measurement run to 30 minutes. Delete each copy as soon as its probes finish and delete the source at the end. Re-list in cleanup. [Billing](https://docs.orgo.ai/guides/billing) · [Create](https://docs.orgo.ai/api-reference/computers/create)
- Record balance before, immediately after and again after a short delay. Use monotonic elapsed time for API calls and readiness polls. Record HTTP status and error body with secrets removed. Record UTC timestamps and short IDs. Report N, min, median, nearest-rank p95, max, and distinguish completed samples from rejected attempts. A gate ends repetitions of that operation. Unexpected responses or unusable accounting end further allocation.
- Estimate effective per-running-minute cost from observed balance and compute transaction deltas, accounting for stopped disk time, concurrent source time, and prepay/refund if present. Report branch-window balance changes with the source cost included unless history can attribute charges. Compare with second-granularity published rates. If billing lag or cent rounding prevents rate identification, report that limit. Caller-written state probes carry no separate verification fee in the published pricing. Orgo action delivery does not provide a verified outcome. [Pricing](https://docs.orgo.ai/guides/pricing) · [Teardown](../../findings/m2-01-competitive-teardown.md#72-orgo-orgoai-docsorgoai)

## Measurements and pass criteria

| Experiment | Planned N | Measurement and pass criteria |
| --- | ---: | --- |
| E0 Small Linux create | 1 | Time from POST to running, confirm actual Small size, record balance change and reconcile rate in E6. Record the workspace-authenticated watch link outside the repo as soon as the computer exists. |
| E1 Plant and read back | 1 | A Python process increments a RAM counter every 100 ms, publishes it to tmpfs, and logs a 20 ms heartbeat. Confirm an increasing counter, process environment marker, tmpfs marker, disk marker and guest boot ID via bash. Show the counter in a guest terminal if available. |
| E2 Running fork | 5 | Record API time, first successful bash, maximum source heartbeat gap across fork, changed UUID and VM instance ID, forced always-on, carried RAM/process/environment/tmpfs/disk and independent writes. Orgo documents a running Linux source and about two seconds of source pause. A 409 `HOURLY_QUOTE_REQUIRED` says the copy needs a purchase. Check for a documented existing-credit-only path before any follow-up. Record the gate when the documented endpoint offers no such path. [Fork](https://docs.orgo.ai/api-reference/computers/fork) |
| E3 Clone | 5 | Time to running. Disk marker persists, process and tmpfs marker are gone, boot ID changes. Record cost and any plan or hourly purchase gate. [Clone](https://docs.orgo.ai/api-reference/computers/clone) |
| E4 Stop/start and suspend/resume | 1 each | Measure stop to stopped/frozen and start to running. Disk persists, process/tmpfs disappear and boot ID changes. Probe bash while stopped and record any `computer_asleep`. Replant before suspend. A plan saves memory and resume restores it. Hourly uses stop instead (409 `HOURLY_USE_STOP`). Resume only if the source is suspended, and verify RAM and disk then. [Stop](https://docs.orgo.ai/api-reference/computers/stop) · [Start](https://docs.orgo.ai/api-reference/computers/start) · [Suspend](https://docs.orgo.ai/api-reference/computers/suspend) · [Resume](https://docs.orgo.ai/api-reference/computers/resume) · [Agent API guide](https://www.orgo.ai/orgo.md) |
| E5 Stopped fork | 1 | Stop the source again and capture the exact response. Documented outcomes include 409 `computer_asleep` and 409 `NOT_FORKABLE` for a non-running, Windows or older VM source. Never provisioned is documented as 400 `NOT_FORKABLE`. Windows, older VMs and never-provisioned sources are outside scope. [Fork](https://docs.orgo.ai/api-reference/computers/fork) |
| E6 Reconcile | 1 | Compare the ledger total, ending balance and billing history after standalone cleanup, with an empty computer inventory. Record any uncertainty from delayed accounting. |

A failed eligibility check yields zero compute samples for E0–E5. Report it as a precondition with its evidence and keep documented semantics distinct from live outcomes. This protocol does not test other sizes, other operating systems, scale, paid-plan-only capabilities, or any end-to-end claim about attempts to verified.

## Amendment 1: Medium gate-probe (adopted after the preflight gate)

Added in a new commit after the pre-registered text above and after the preflight result was known. The original text is unchanged. This amendment does not rewrite any earlier rule or result: it narrows what is run under the outer loop's later approval. The outer loop (Discovery owner) approved it on 2026-11-21 23:58 ET: budget $0.25 total, hard stop $0.15 observed spend. The earlier "smallest machine only" rule was a cost preference; Medium is the smallest size the Free tier is offered. Full text and rationale: [PROPOSED-AMENDMENT.md](PROPOSED-AMENDMENT.md).

1. On a Free account a single Medium may be created only as a gate-probe for E0, E1, E4 and E5, and to observe the E2 and E3 gates.
2. Probe budget $0.25 total, hard stop at $0.15 observed spend, `ends_in_hours` 1, and a 20 minute deadline enforced in the polling loops.
3. Cleanup deletes every computer present now that was absent at preflight, or in the created-id set, regardless of name. The source is named `myco-discovery-base`.
4. E2 and E3 become N=1 gate observations: record the first response. On 403 `HOURLY_LIMIT` or 409 `HOURLY_QUOTE_REQUIRED` stop that experiment: no purchase, no further attempt.
5. E4 suspend is a single probe expecting 409 `HOURLY_USE_STOP`. E5 keeps `allow()`. Sample counts are N=1 and no p95 is claimed.
6. Medium results are not Small results: report the size obtained, and do not compare latency or price across sizes.
7. The raw preflight JSON stays committed.

Still not approved: any paid Orgo plan, top-up or purchase. Fork and clone timing remain documented, gated results. The runner stays marked NOT CLEARED FOR LIVE USE until the outer loop confirms an independent re-verification of the fixes, and explicitly clears a live run.

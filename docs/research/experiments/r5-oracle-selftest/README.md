Generated by `npx tsx scripts/oracle-selftest.ts --write`. Do not edit by hand:
`--check` rebuilds this file and `report.json` byte for byte and fails on any difference.

Each oracle is run through its real read path on seeded corruptions of a correct saved
document. **Bar:** every correct document verifies, and for every class the oracle
*claims*, at least one corruption is run and none of them verifies. A corruption whose
bytes equal the correct document is a harness fault and fails the bar. Unclaimed classes
are run and reported but do not count toward the bar: a verified unclaimed row is a
visible gap, not a pass. **A PASS means the claimed classes are caught, nothing more.**

## What this report shows (each statement is asserted by `test/oracle-selftest/`)

- **Collateral damage** (target right, other content changed) verifies on M1's
  `calc-record-edit/csv` verifier and on `writer-doc-edit`: both check the target only.
  The gate's `calc-record-edit` family (version 2, TIF-270 / #485) reads the same CSV
  bytes, checks the whole document, and refutes every collateral corruption.
- **A truncated CSV** verifies on M1's CSV verifier exactly when the target cell
  survives the cut: CSV has no integrity marker, and that verifier reads one cell. The
  gate's whole-document check refutes every truncated CSV (the missing rows differ).
- **`writer-doc-edit` PASS is not whole-document correctness:** it does not claim
  collateral, and a collateral corruption verifies on it.
- Classes marked *not applicable* were not run for that oracle: a CSV has no container,
  so `corrupt-byte`, `partial-save` and `missing-main-part` have no CSV form.
